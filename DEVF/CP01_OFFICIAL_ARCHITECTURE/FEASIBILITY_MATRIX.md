# Matriz de viabilidad del producto completo

A = capacidad disponible con evidencia suficiente; B = posibilidad fundamentada que necesita experimentos; C = función no demostrada o método incompatible. `PASS` aquí es estático o de laboratorio según se indica; jamás render/DX12 runtime. `PARTIAL` cubre una parte concreta del objetivo. `NOT_VERIFIED` no equivale a imposible. `BLOCKED` exige resolver un requisito previo. `NOT_FEASIBLE` se aplica al **método expresamente excluido**, sin descartar toda alternativa para la función.

Fuentes con SHA256 y líneas: [source-references.json](evidence/source-references.json). Comparación de entradas/ownership: [ROUTES_AND_CONTRACTS.md](ROUTES_AND_CONTRACTS.md). Ninguna variante avanzada se ha activado o implementado en este checkpoint.

| Función del objetivo | Ruta oficial y evidencia | Clase / conclusión | Evidencia pendiente y alternativa compatible |
|---|---|---|---|
| Definir colocación de enemigo original sin reemplazos | StageService 1.0 copia ACTR/TGSC; dStage crea perfil nativo con post-callback NULL. | **A / PASS estático**; aparición **NOT_VERIFIED**. | Recursos, FILI, room/layer y transiciones reales. Conflictos con overrides de otros mods. |
| Solicitar enemigo original con ID propio | ActorService create por nombre o ProfileName, callback NULL. | **A / PASS estático** para solicitud; readiness **NOT_VERIFIED**. | Observar creación completa/fallo y escena; no confundir ID de request con actor listo. |
| Persistencia de colocaciones | Ediciones Stage permanecen activas y se consumen en roomReLoader; reconstituir desde Host.data_dir. | **A / PARTIAL**. | No garantiza identidad de instancias, unicidad, eliminación al retirar ni comportamiento al hot reload. Alternativa: controlador A2 con configuración propia, sin registrar A1 a la vez. |
| Identificación individual | A2 devuelve ActorId; ABI tiene búsqueda por ID. A1 entrega solo handle de edición. | **B / PARTIAL**. | No usar primer actor por perfil/posición como prueba de ownership. Probar IDs, readiness, cambios de escena y agotamiento/reutilización; no persistir IDs entre sesiones. |
| Vida por instancia | `fopAc_ac_c::health` s16; E_rd inicializa a 40 y su daño consulta ese campo. | **B / PARTIAL**. | Puede sobrescribirse: E_rd tiene rutas health=100/0. E_SB mantiene además salud propia `field_0x5e6`. Adaptadores por enemigo, valores/rango/momento; no escribir HIO ni compensar daño a ciegas cada frame. |
| Daño por instancia | Colliders oficiales: SetAtAtp/GetAtAtp/SetAtType; `dCcU_AtInfo::mAttackPower`. | **B / NOT_VERIFIED**. | El daño final depende de atacante, víctima y cc_at_check; mAttackPower se recalcula, no es setter persistente de ataque. Validar collider real, resets por estado y timing. No callbacks de impacto DLL sin contrato de retirada seguro. |
| Defensa por instancia | OnTgShield/OffTgShield de collider y estados públicos de enemigos concretos. | **B / PARTIAL** para mecanismos de escudo; defensa numérica universal **C / NOT_VERIFIED**. | Escudo ≠ reducción porcentual. Medir pipeline por enemigo; alternativa compatible: presets nativos y una política documentada por collider/estado, sin parchear la función de daño. |
| Tamaño independiente | TGSC/ActorSpawnParams suministran scale; E_rd usa `scale.x * l_HIO.model_size`. | **B / PARTIAL**. | E_rd hace escala visual uniforme y configura radios por separado; E_SB usa solo l_HIO.size e ignora scale. Probar modelo, culling, suelo, colisión y alcance por tipo. Cambiar l_HIO global: **C / NOT_FEASIBLE** bajo la restricción por instancia. |
| Velocidad | speed/speedF y helpers oficiales por instancia; estados propios de cada enemigo. | **B / PARTIAL**. | Execute/IA pueden reemplazarla cada tick desde HIO. Estudiar un adaptador concreto y orden de mod_update/actor Execute, sin reubicar por frame para fingir física. |
| IA y comportamiento configurable | Parámetros nativos seleccionan modos; E_rd tiene estados públicos mode/action/timers y recursos propios de cada modo. | **A / PARTIAL** para selección limitada de modos documentados; controlador externo ABI **B / NOT_VERIFIED**. | Un modo no es IA arbitraria. Un controlador en mod_update podría ajustar estados permitidos por enemigo, con pruebas de invariantes, sin sustituir execute/vtable ni enganchar funciones. IA nueva universal por hooks/detours: **C / NOT_FEASIBLE** para ese método. |
| Frecuencia de ataques | Timers/estados por instancia en E_rd; diversos intervalos proceden de HIO/KREG compartidos. | **B / NOT_VERIFIED**. | Determinar timers causalmente relevantes y cuándo se recargan. Alternativa: adaptar enemigos que ya expongan temporización por instancia; no modificar tablas globales ni asumir un timer universal. |
| Apariencia independiente/materiales | TextureService 1.0, J3DModel/MatPacket y GfxService 1.4 oficiales. | **B / PARTIAL** para herramientas; skins por instancia **NOT_VERIFIED**. | TextureKey SOURCE es hash y POINTER es texel-data, no ActorId. J3DModelData/materiales pueden compartirse aunque haya paquetes por modelo. No mutar modelo/textura compartidos. Investigar aislamiento real/copia gestionada y destrucción, o render propio vía Gfx; overlay/tint adicional sería una alternativa parcial, no equivalente automático a skin completa. |
| Efectos independientes | ABI expone funciones de partículas; SDK Gfx admite draw/encoder callbacks propios con ownership de servicio. | **B / PARTIAL**. | Recursos de efecto, ID de emisor, duración y retirada. Evitar callbacks DLL en modelos, emisores/colliders nativos y referencias prestadas fuera de su tick. Gfx unregister/synchronize tiene barrera estática; falta prueba DX12 y teardown del uso concreto. |
| Recompensas por instancia | ItemService 2.3: resolvers/observers y giver_actor cuando existe; give_item encola grants. | **B / PARTIAL** para canales oficiales; muerte→recompensa de cualquier enemigo **NOT_VERIFIED**. | No hay evento universal de muerte en ActorService. Desaparición puede ser cambio de sala/fallo. E_SB crea DISAPPEAR; este consulta tabla EnemyID y crea ítem sin transmitir un giver de E_SB a una regla universal. No alterar tablas globales ni override de check para simular instancia. Alternativa: adaptador de muerte confirmado y grant oficial propio, evitando duplicar drop vanilla. |
| Configuración de atributos y colocaciones entre sesiones | Host 2.2 data_dir; Resource 1.1 res propio; File 1.0 acceso a ficheros propios/selección de usuario. | **A / PASS estático** para almacenamiento propio; esquema/editor **B / NOT_VERIFIED**. | Validación de datos, migraciones, escritura atómica y reconstitución controlada. data_dir no es un save del juego. No usar mod_dir temporal como persistencia. |
| Editor dentro del juego | UiService oficial: tabs, controles y callbacks; File picker y Gfx disponibles. | **A / PASS estático** para UI/servicios; editor funcional **B / NOT_VERIFIED**. | UI elimina slots y verifica slot_live; File anula callback del picker al detach. Probar su uso real, captura de escena/posición, conflictos, undo, ownership y validación. El editor no puede eludir gates de aparición. |
| Cave Framework / Dungeon Framework | Configuración portable propia, servicios declarados con versión y orden de imports, vigilancia de detach por Host. | **B / NOT_VERIFIED**. | No hay contrato suministrado de esos futuros frameworks. Proponer IDs de colocación, proveedor de contexto stage/room/layer, claims de ownership y coordinación de transiciones. No prometer compatibilidad ya probada. |
| Tipos nuevos con perfiles DLL de DEVF | ActorService register/unregister original. | **C / BLOCKED** como arquitectura actual. | El bloqueo independiente de ciclo de vida oficial se conserva. No registrar perfiles ni adoptar el parche experimental. Alternativa compatible a estudiar: perfiles originales con adaptadores limitados y control externo, sin prometer que cubren todo tipo nuevo. |
| Retirar automáticamente todo enemigo al desactivar | Stage no devuelve IDs; Actor.delete no acredita cancelación pre-create; no inventario nativo por propietario. | **B / BLOCKED** para garantía general. | Política pasiva: quitar definiciones futuras y dejar actores nativos al host hasta destrucción/fin de proceso. Si el producto exige desaparición inmediata de todos, demostrar cancelación y binding con APIs oficiales antes de prometerla. |

El alcance original permanece: atributos, aspectos e IA independientes, colocaciones persistentes, editor e integración futura. A1 resuelve una primitiva de colocación; **no constituye el producto completo ni acredita GO de CP02**. La ruta B conserva posibilidades concretas sin tratar acceso a datos públicos como estabilidad semántica o seguridad de ejecución.
