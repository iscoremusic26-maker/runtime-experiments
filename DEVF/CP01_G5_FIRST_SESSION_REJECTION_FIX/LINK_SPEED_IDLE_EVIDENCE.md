# Velocidad e inmovilidad: qué está probado

Dusklight2.0.3 Windows x64/DX12. **DISARMED_NO_REGISTRATION / READ_ONLY_DIAGNOSTIC / NEXT G5 NOT AUTHORIZED.**

[f_op_actor.h](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/include/f_op/f_op_actor.h) publica cXyz speed yfloat speedF. El collector copia esos floats solo de la fila que el visitor identifica como player real, tras verificar cabecera/INIT; el bridge cruza ID y copia group/speed de esa misma fila. assess/freshness comprueban la coherencia con Link y actor rows. El tracker diagnóstico ahora también exige esa coincidencia; NaN/Inf o datos parciales no certifican delta.

[f_op_actor_mng.cpp](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/f_op/f_op_actor_mng.cpp), calcSpeed: X/Z desde speedF y seno/coseno, Y+=gravity con clamp; posMove suma velocidades. [daAlink::posMove](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/d/actor/d_a_alink.cpp#L13013) calcula speedF desde mNormalSpeed/modificadores/pendiente, X/Z desde yaw, gravedad según estado, suma speed a posición y aplica correcciones adicionales de colisión/wind/polígono. Por tanto velocidad almacenada no equivale necesariamente al delta final tras correcciones. No se modifica HIO ni movimiento. El callback anterior al management puede observar resultados del tick anterior; no promete datos futuros ni atomicidad externa.

El log recibido no conserva componentes numéricos. No permite decidir cuál eje ocasionó LINK_MOVING ni calibrar tolerancia. **LINK_IDLE_CRITERION_UNVERIFIED**. La política sigue speedXYZ==0 yspeedF==0 exactos/finito; incluso un denormalfloat32 no cero se rechaza. No epsilon ni ignorar Y ni ventana que conceda permiso.

Temporal registra solo dos capturas completas en updates diferentes consecutivos, identidad/contexto estables, velocidades finitas y coincidencia con fila Link. gap1 produce deltaXYZ; mismo update nunca certifica duración idle, gap>1 informa Skipped y no interpola; rewind/transition/event/censo inválido/Link perdido cambian o reinician historia. Desplazamientos se miden, no se toleran con un umbral inventado. A/B/C en el mismo update continúan siendo freshness inmediata, no30frames de reposo.

La nueva traza representa speedXYZ/speedF con9 cifras significativas parafloat32, máscara de ceros y clase negativa/cero/positiva/no finita por eje; delta_gap/previous_update/status. Datos no finitos se imprimen UNAVAILABLE; Link ground=NOT_OBSERVED_SAFE_API, pues GroundCross en C no es suelo de Link. Una futura captura diagnóstica consentida deberá relacionar velocidades, deltas y estado visual de reposo/movimiento antes de proponer otra política activa. Esa captura no está autorizada aquí.
