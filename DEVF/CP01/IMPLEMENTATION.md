# Implementación actual CP01
La base sigue siendo el wrock del demo exacto 2.0.3, perfil dvfrock, modelos/collider por instancia y BMD/DZB nativos mediante gestor de recursos. Código completo en src/; sin offsets/vtables copiados ni enemigos retail. El perfil y las rutas Actor/Stage se compilan, pero no se registran ni se ejecutan en producción de esta revisión.

Controller separa Stage edits y runtime, controla duplicados/rollback, conserva handles en errores y rechaza un post-create callback adicional. start_guarded requiere evidencia de lugar, drenado, colisión y barrera host. No existe esa acreditación y mod_initialize termina en modo diagnóstico cerrado, sin ownership en el engine. La política empaquetada no abre activación al editarla.

ResourceLifecycle usa fases de carga, estado ready/closing, fallos terminales y release verificable. Ante release de colisión/archivo fallido no libera referencias y no puede volver a ejecutar/dibujar/cargar. Rock realiza el cleanup antes de destructor y respeta fallo local; el forceDelete del host puede ignorar ese resultado, por lo que la implementación activa permanece bloqueada. Heap callback reinicia refs y failure limpia punteros a heaps ya destruidos; execute no accede antes de ready. La fase de archivo distinta de id 2 se conserva como bloqueo en vez de llamar resDelete inválido.

Los aspectos conocidos del orden de shutdown (ActorService pre-hook, StageService detach) se conservan; no se asume que shutdown failure retenga la DLL. Las cinco funciones upstream extraídas solo se incluyen en el EXE de laboratorio con tipos/backends simulados, nunca como estructura ABI o código de hook del mod.

Auditorías completas en LIFECYCLE_AUDIT.md y LOCATION_EVIDENCE.md. Esos documentos sustituyen las interpretaciones incompletas del checkpoint inicial sin modificar su historial. Runtime de heap/mount, dibujo, colisión y escenas/DX12 NOT_TESTED; pruebas nuevas y reg específicas en TEST_RESULTS.

El adaptador CollisionOps usa GetBgWBasePointer/ChkPolySafe y una identidad cBgS_PolyInfo sin consultar geometría ni offsets privados. release_owned_collision recorre los 256 slots exactos buscando el collider propio: ausencia de referencia implica retirar solo el ID local; identidad/index/actor incorrectos o duplicados implican fallo y retención. La retirada global se permite solo para la referencia única con owner correcto. Esto protege una referencia local obsoleta durante cambio de escena, pero no aporta barrera de DLL ni prueba de motor.
