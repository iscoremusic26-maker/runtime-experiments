## Estado y entrada al tick

AchievementSystem es singleton; su constructor obtiene entradas de makeEntries. Cada Entry combina estado de logro, callback check y JSON extra. El estado incluye progress/unlocked; las señales viven en un mapa con claves string_view y contador, no en una cola por slot. getAchievements devuelve una copia de los registros para la UI. **PORT-001**, [tipos/estado L32-L67](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/dusk/achievements.h#L32-L67), [singleton/snapshot L1179-L1193](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/dusk/achievements.cpp#L1179-L1193).

El consumidor de engine llama tick después de fpcM_Management y GameMode tick. Dentro de AchievementSystem, solo vanilla o speedrun pasan el gate; otros modos limpian señales y retornan antes de load/procesamiento. En modo aceptado, la carga es lazy; si IsGameLaunched sigue false se retorna **antes** de limpiar las señales. En el camino normal, todos los checks ven la misma colección y se limpia al terminar el recorrido. La frase del header “clear each tick” debe leerse con esos gates. **PORT-002**, [tick L1305-L1325](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/dusk/achievements.cpp#L1305-L1325), [caller L824-L842](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/f_ap/f_ap_game.cpp#L824-L842).

## Una cadena juego → señal → check → progreso

El menú de cartas marca la carta leída y emite signal("open_letter") en TARGET_PC. signal incrementa un contador. Un check representativo combina esa señal con presencia de un actor obtenida por SearchByName y fija progress; no deduce el logro únicamente del texto o de abrir una ventana UI. processEntry omite logros ya unlocked, ejecuta el check y determina si progress alcanza goal (contador) o es positivo (no contador). Al desbloquear, normaliza progress, fija unlocked y opcionalmente emite toast. Solo cambio de progress o unlock marca m_dirty en esa función. **PORT-003**, [emisor L594-L604](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/d/d_menu_letter.cpp#L594-L604), [check L774-L788](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/dusk/achievements.cpp#L774-L788), [señales L1250-L1262](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/dusk/achievements.cpp#L1250-L1262), [proceso L1276-L1302](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/dusk/achievements.cpp#L1276-L1302).

Esto no es auditoría de todos los criterios. El mapa de señales guarda string_view; el emisor elegido usa literal de duración estática. No se deduce lifetime seguro para una clave temporal aportada por un caller distinto, ni concurrencia libre para cambiar ese mapa.

## Persistencia y fallos

load fija m_loaded antes de comprobar/leer el archivo de ConfigPath. Espera objeto JSON, recorre solo keys de entradas conocidas y recupera progress, unlocked y extra. Captura std::exception sin propagar. Como aplica por campos dentro del bucle, una excepción tardía no revierte campos previos; el flag loaded tampoco significa lectura íntegra exitosa. **PORT-004**, [load L1195-L1223](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/dusk/achievements.cpp#L1195-L1223).

save serializa un objeto por achievement.key con progress/unlocked y extra cuando no nulo. Es archivo propio `achievements.json`; no usa SaveService ni índices de slot en esta serialización. El helper hace Create/Write/Flush, y save captura excepciones sin retornar resultado. tick llama save cuando dirty y después deja dirty=false. Si ocurre una excepción capturada, ese camino no preserva una marca de reintento; una confirmación UI o el retorno void no prueban durabilidad. **PORT-005**, [save L1225-L1243](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/dusk/achievements.cpp#L1225-L1243), [writer L178-L182](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/dusk/io.cpp#L178-L182), [dirty L1321-L1325](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/dusk/achievements.cpp#L1321-L1325). No se simuló error de disco ni se inspeccionó un archivo personal.

La UI usa getAchievements para obtener snapshots y compara size/progress/unlocked al refrescar. clearAll y clearOne reconstruyen o resetean estado y llaman save directamente; no se ejecutaron esas acciones. Ventana abierta, toast visible, logro calculado y estado persistido son hechos distintos. **PORT-001/005**, [UI L103-L108](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/dusk/ui/achievements.cpp#L103-L108), [refresh L182-L191](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/dusk/ui/achievements.cpp#L182-L191), [reset L1245-L1274](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/dusk/achievements.cpp#L1245-L1274).

## Frontera .dusk y pendientes

El comentario del gate anticipa AchievementService, pero el registro del SDK en este pin no lo publica; no convertir una intención en API oficial. Las funciones internas indexadas son POTENTIAL_REQUIRES_VERIFICATION, sin export/ABI/target Windows observado. No hay contrato oficial aquí para registrar nuevos logros desde .dusk. **PORT-002**, [registro de módulos L263-L296](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/dusk/mods/svc/registry.cpp#L263-L296).

No se recomienda editar estado personal ni implementar un mod mediante escrituras al archivo. Quedan pendientes checks no muestreados, lifetime general de signals, errores de JSON/IO reproducidos y rutas de reset/mode transition completas. Ninguna observación de cuenta, UI, audio o juego fue realizada.
