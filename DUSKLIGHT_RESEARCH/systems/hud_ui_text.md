# HUD, UI, mensajes, fuentes e idioma

Fuente: `TwilitRealm/dusklight@40457c6adb381928e4b5fef6ed459ed291edd5e2`. Objetivo: Dusklight 2.0.3, Windows x64, DX12, GZ2E01. Esta ficha registra inspección estática; no se ejecutó el juego ni un mod. Los símbolos del juego que aparecen aquí no tienen disponibilidad de enlace ni hook demostrada por su mera existencia.

## HUD original y estado

`dMeter2_c::_create` inicializa estado desde save/play: vida, aceite, oxígeno, rupias, inventario y equipamiento. `_execute` cambia al heap del HUD, comprueba estado, ejecuta `mpMeterDraw` y actualiza medidores/botones. Contiene reconciliación de flags de colección con eventos; no es una capa exclusivamente visual. `_draw` encola mapa/subcontenidos/HUD, pero TARGET_PC omite dibujo por recordingMode/minimalHUD/debugFlyCam. `_delete` elimina subobjetos y heaps propios. **PRES-019**: [src/d/d_meter2.cpp](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/d/d_meter2.cpp#L69-L170); [src/d/d_meter2.cpp](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/d/d_meter2.cpp#L268-L301); [src/d/d_meter2.cpp](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/d/d_meter2.cpp#L347-L435).

Por ello cambiar solo el dibujo no necesariamente cambia la fuente de verdad de inventario/vida, y modificar save para producir un efecto visual puede tener consecuencias persistentes. Véanse [inventario](inventory_equipment.md), [guardado](save_load.md), [progresión](flags_events_progression.md). `UiService` para UI del mod, `WindowService` para ventana y Gfx antes/después del HUD son rutas oficiales distintas del actor `dMeter2`; su matriz está en [SDK](../SDK_AND_SERVICES.md). No asumir que `UiService` reemplaza panes J2D del juego.

## Mensajes: contrato existente

`MessageService.override_message` valida grupo, rango de ID y texto codificado; copia bytes y produce handle owned. La variante callback conserva fn/user_data, no sus objetos externos. `valid_encoded_text` exige terminador al final, tamaños de tags válidos y restricciones para color; no es un traductor genérico de string UTF-8. Resolución busca `(group,id,active_language)`, prioriza mod posterior y secuencia posterior; callback aceptado se copia a vector compartido, texto mal formado falla el mod. **PRES-020**: [src/dusk/mods/svc/flow.cpp](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/dusk/mods/svc/flow.cpp#L455-L481); [src/dusk/mods/svc/flow.cpp](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/dusk/mods/svc/flow.cpp#L514-L566); [src/dusk/mods/svc/flow.cpp](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/dusk/mods/svc/flow.cpp#L1272-L1315).

`register_message` crea ID del pool custom y variantes por idioma; devuelve `MOD_UNAVAILABLE` si agota el pool y rechaza datos inválidos/idiomas duplicados. `resolve_message_entry` valida que el grupo exista y que la variante activa esté presente; no inventa fallback universal. **SOURCE_OBSERVED**: [src/dusk/mods/svc/flow.cpp](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/dusk/mods/svc/flow.cpp#L814-L837); [src/dusk/mods/svc/flow.cpp](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/dusk/mods/svc/flow.cpp#L1337-L1373). Para navegación y acciones de diálogo véase [cutscenes/dialogue](cutscenes_dialogue.md).

## Idioma del disco y assets

`dusk::language::available_languages` depende de región, plataforma y revisión; Norteamérica ofrece English salvo Wii revision2, que añade French/Spanish. La selección de `msg_folder` utiliza Msgde/Msgfr/Msgsp/Msgit/Msgjp o Msgus/Msguk según idioma/región. Esto no demuestra que un disco GZ2E01 contenga cada variante ni cada glifo; no inferir paridad Wii/GC. **PRES-021**: [src/dusk/language.cpp](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/dusk/language.cpp#L8-L38); [src/dusk/language.cpp](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/dusk/language.cpp#L59-L76).

Integración: `OFFICIAL_SERVICE` para mensajes y UI custom; `ASSET_OVERLAY` para recursos de layout/font compatibles; modificación directa del HUD/J2D sigue `POTENTIAL_REQUIRES_VERIFICATION`. Retirar overrides y callbacks propios antes de unload; esperar nueva resolución de mensajes/recarga de recursos para consumidores ya vivos. **Pendiente**: decodificación BMG por charset completo, J2D layout/font lifecycle, binding de botones y todas las pantallas de menú. No se ofrece prueba de sustitución gráfica en Windows.

Cobertura: READ/CROSSCHECKED selectiva según SYSTEM_INDEX y los niveles de cada evidencia; ninguna ruta constituye prueba runtime Windows/DX12.


## CP-R07 — fuente compartida: adquisición, panes y liberación

Cadena seleccionada: logo → FontArchive → mDoExt_initFont0/initFontCommon → JUTResFont → dFile_info_c/J2DTextBox → destructor del consumidor y removeMesgFont. Es una ruta contrastada de fuentes/layout, sin declarar todo HUD CROSSCHECKED.

El logo elige Fontus/Fonteu/Fontjp, solicita montaje de fontres/rubyres y publica FontArchive. Después llama getMesgFont y adquiere una referencia global; en PC la rama japonesa puede desmontar FontArchive tras iniciar la variante cacheada. La otra rama inicia JUTResFont desde `rodan_b_24_22.bfn` con heap Zelda y conserva recurso, por lo que no se deduce unmount seguro universal. **PRES-036**, [logo L1668-L1681](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/d/d_s_logo.cpp#L1668-L1681), [publicación/adquisición L960-L1009](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/d/d_s_logo.cpp#L960-L1009), [init común/regional L3709-L3777](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/m_Do/m_Do_ext.cpp#L3709-L3777).

getMesgFont inicializa al primer uso e **incrementa** un contador global. El file-selector crea instancias dFile_info_c; screenSet carga `zelda_file_select_info_text.blo`, adquiere una referencia y la entrega a dos text boxes. Su destructor destruye pantalla/gestores antes de removeMesgFont. No es adquisición por cada pane: setFont no incrementa ese contador. **PRES-037/038**, [consumidor L22-L80](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/d/d_file_sel_info.cpp#L22-L80), [creación por selector L3625-L3630](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/d/d_file_select.cpp#L3625-L3630), [get/remove L3780-L3813](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/m_Do/m_Do_ext.cpp#L3780-L3813).

J2DTextBox elimina su fuente previa solamente si mTextFontOwned era true; setFont guarda el puntero nuevo y cambia ownership a false. El destructor elimina font solo cuando owned, además del buffer de string. El consumidor debe conservar el font compartido hasta terminar todos los panes que lo prestan. JUTResFont a su vez conserva ResFONT y punteros a WID1/GLY1/MAP1 del backing; sus tablas de punteros son allocations propias, pero no constituyen copia profunda del BFN. La liberación del recurso ocurre en el owner externo de mDoExt, no por asumir que todo font destruye su backing. **PRES-038/039**, [TextBox L241-L257](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/libs/JSystem/src/J2DGraph/J2DTextBox.cpp#L241-L257), [ResFont L94-L127](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/libs/JSystem/src/JUtility/JUTResFont.cpp#L94-L127), [punteros a bloques L169-L201](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/libs/JSystem/src/JUtility/JUTResFont.cpp#L169-L201).

En PC protected_initiate entra a initJoinedTexture: exige un único bloque GLY y ancho/alto múltiplos de ocho, y prepara un objeto de textura con las páginas. Son restricciones reales del código, sin demostrar que cualquier BFN de otra revisión o un charset nuevo sea válido. El camino de error de initiate limpia tablas y marca invalid; no se probó una fuente corrupta ni un frame renderizado. **PRES-039**, [construcción/destructor L17-L56](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/libs/JSystem/src/JUtility/JUTResFont.cpp#L17-L56), [restricciones PC L59-L90](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/libs/JSystem/src/JUtility/JUTResFont.cpp#L59-L90).

La función removeMesgFont contiene un assert >0 después de decrementar y antes de la rama ==0. Se conserva ese detalle sin prometer que la última liberación se haya probado bajo cualquier configuración de asserts; el bootstrap mantiene otra adquisición y no se auditó el balance global de todos los menús.

Para .dusk: ASSET_OVERLAY es mecanismo de recursos ya documentado, pero no garantiza sustituir un font o layout actualmente cacheado. Acceso C++ a estas funciones sigue POTENTIAL_REQUIRES_VERIFICATION. UiService no transfiere automáticamente ownership de panes J2D ni reemplaza este circuito. Rollback debe respetar panes, referencia global y backing resource; no liberar bytes mientras font siga apuntando a ellos. Pendiente: todos los charsets/BMG, cache-font japonés completo, TextBoxEx, errores del montaje y todos los consumidores.
