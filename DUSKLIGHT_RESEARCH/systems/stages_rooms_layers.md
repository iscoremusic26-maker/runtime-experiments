# Stages, salas, capas y transición

Fuente: `TwilitRealm/dusklight@40457c6adb381928e4b5fef6ed459ed291edd5e2`. Objetivo documental: Windows x64 / DirectX 12 / disco GZ2E01. Evidencia exclusivamente estática de este checkpoint; ni ejecución Windows ni juego vivo verificados. Los símbolos internos se localizan para investigación: su disponibilidad enlazable y su instalación mediante HookService requieren verificación aparte.

**Profundidad: flujo transversal contrastado; formatos y transición examinados por rutas concretas, sin auditoría completa de cada stage.** Proveedores: recursos de disco, memoria de progreso y scheduler de procesos. Consumidores: actores, cámaras, eventos, ambiente y guardado. El stage contiene metadatos; la sala es un proceso con recursos y heap propios; la capa selecciona variantes del contenido. La selección de capas puede leer progresión y estado de Twilight: `getLayerNo_common_common` contiene ramas concretas por stage y eventos. Esto impide asumir que una sala con el mismo número presenta idéntico contenido en todos los saves. ## DZS/DZR y límite de StageService

El formato tiene contador de chunks y nodos con tag, número de entradas y offset. PC usa `BE(...)` y `OFFSET_PTR...`; `dStage_dt_c_offsetToPtr` establece base de offsets, mientras la rama de consola usa aritmética de direcciones. `dStage_dt_c_decode` busca tags en una tabla de consumidores. No copiar offsets de puntero de consola ni reinterpretar un archivo en disco como un objeto nativo completo. ## Salidas y puntos de inicio

`dStage_changeScene(int,f32,u32,s8,s16,int)` obtiene SCLS del stage o sala, valida índice con assertions, lee stage/start/room/layer/wipe/time y llama `dComIfGp_setNextStage`. Este último también registra última estancia y modo de escena, actualiza información de restart y eventualmente start-point. `dStage_playerInit` distingue restart de habitación, turn-restart y punto explícito; el PC incorpora edición/añadido de puntos Link. **POTENTIAL_REQUIRES_VERIFICATION** para intervención C++ en estas funciones; StageService no es un servicio genérico de teletransporte. ## Colisión y scheduler: fronteras relevantes

KCL existe realmente, además de DZB: el cargador distingue `'DZB '` → `cBgS::ConvDzb` y `'KCL '` → `dBgWKCol::initKCollision`. Este último establece offsets y convierte datos endian para PC; `dBgWKCol::create(void*,void*)` exige también PLC. StageService no contiene API para editar geometría, KCL/PLC ni navegación. **ASSET_OVERLAY** es una ruta documental candidata para sustituir un recurso; geometría válida y coherencia KCL/PLC/modelo requieren validación independiente. [WORLD-031] [src/d/d_resorce.cpp:529](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/d/d_resorce.cpp#L529-L533), [src/d/d_bg_w_kcol.cpp:22](https://github.com/TwilitRealm/dusklight/blob/40457c6adb381928e4b5fef6ed459ed291edd5e2/src/d/d_bg_w_kcol.cpp#L22-L70).

`fpcM_Management` ejecuta eliminación, prioridad, creación, callback previo, ejecución de procesos, dibujo y callback posterior dentro de condiciones de error/captura. Ese orden observado no significa que todo actor ejecute una vez por frame visual o durante pausas.
