## Entrada y gates

PORT-014: startup crea CommandConsole como unique_ptr y la entrega a push_document con show=false. La consola declara permanent=true; eso no significa visible ni activa. handle_event intercepta slash Keydown si enableAdvancedSettings; exige documento encontrado,input no activo,no repeat y shortcut no retenido. KeyUp/focus lost liberan el latch. show y update añaden gate de prelaunch; recibir tecla no prueba que se haya abierto. Los gates no son un macro DEBUG,una credencial ni autorización de un mod. No se atribuye activación Windows a nombre de plataforma.

El listener Keydown capturando this retorna si !mInputActive. Return llama execute_from_input y detiene propagación; Escape oculta; otras teclas navegan historial/scroll. El caller copia el valor Rml antes de hide(false); si no vacío llama runCommand con mState y lambda que añade cada respuesta al panel. Es llamada directa en ruta de evento UI,sin Task/frameBegin/guarded_callback en esta cadena. No se extiende a ella el contrato de HttpService ni se prueba reentrancia arbitraria.

## Parser y consumidor representativo rate

PORT-015: CommandOutput es std::function<void(std::string)>; CommandState pertenece a la consola,con historial,foundProcId,lastWarpStage y echoEnabled inicialtrue. runCommand emite eco antes de parser/historial si habilitado. Guarda líneas no vacías distintas de la última,hasta64; SplitArgs separa solo espacios/tabs,no interpreta comillas. Una línea de espacios puede entrar en historial y producir cero tokens. Sin tokens retorna; comando desconocido produce respuesta de error. En el archivo se despacha con condiciones por nombre; búsqueda acotada en comandos,SDK headers y registro de servicios no localiza API pública de register/unregister comandos. No se deduce ausencia universal de toda infraestructura de debug.

PORT-016: se elige solo rate. Sin argumento consulta; con argumento ParseLong usa strtol(base0) y exige consumo completo. La rama rechaza parse inválido o <=0; no verifica errno/overflow en el helper leído. Otros argumentos no los usa esta rama. set_sim_rate convierte/clampa a1..maximumHz y llama aurora::time::set_scale; maximumHz se deriva de kMaximumTimeScale/kSimPeriod,kSimPeriod=1/30. No afirmar límite480 por texto de help sin definición del backend ausente. Luego reset reancla muestras,pone simTickActive=false e incrementa presentationEpoch. get_sim_rate lee scale/kSimPeriod y ese valor se formatea para output.

El mensaje Sim rate es lectura del wrapper tras la llamada,no medición de frecuencia,confirmación de backend ni persistencia de configuración. No se siguen otros comandos de gameplay. Aurora es gitlink ausente: semántica interna de set_scale,capacidad efectiva y rendimiento Windows NOT_VERIFIED. Ocultar consola no llama reset ni restaura tasa; la responsabilidad de ese estado global no pertenece a CommandState. No se propone cambiarlo desde un mod.

## Respuesta, ownership y cleanup

PORT-017: append_message recibe string propio,copia texto a UI y mueve string al deque. Element pointers dependen del documento Rml. Se retiran nodos viejos al superar500 entradas; expiración a6s/fade800ms y máximo24líneas visibles no equivalen a borrar inmediatamente historial o mensaje. update solo aplica expiración cuando sus gates permiten; no son tiempos medidos. navigate_history usa CommandState existente. close_input limpia input/foco/posición de navegación,conserva historial y mensajes. hide(true) marca cerrado a través de Document; permanent permite que close_all_documents use hide(false),no inmunidad a destrucción.

push_document mueve unique_ptr al stack; update retira cerrados y shutdown vacía stacks. Document::~Document limpia listeners antes de Close del RmlDocument. listen posee ScopedEventListener,que registra AddEventListener; destructor llama RemoveEventListener si element sigue válido y OnDetach nulifica su referencia. El callback ProcessEvent llama mCallback directamente. No demuestra drenaje de un evento ya ejecutándose ni seguridad de destruir this desde callback/reentrancia arbitraria. Retirar listener UI no retira una rama del dispatcher host. Al destruir consola se destruyen su CommandState/deque; backend de documentos/eventos y render no están certificados por esta lectura.
