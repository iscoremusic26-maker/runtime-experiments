# SDK y servicios de Dusklight 2.0.3

Fuente exclusiva: `TwilitRealm/dusklight@40457c6adb381928e4b5fef6ed459ed291edd5e2`. Plataforma objetivo Windows x64 / DirectX 12; aquí se contrastan contratos y fuente, sin ejecución Windows ni del juego. Estado global: **STATIC_CROSSCHECKED**, con profundidad desigual explícita.

El inventario contiene **25 encabezados C de servicio, 25 IDs y 26 módulos candidatos enumerados por el registro**, porque UI conserva las versiones 1.5 y 2.3. Los nueve `.hpp` de `svc/` son ayudas C++ de esos contratos; no cuentan como servicios adicionales. La disponibilidad real puede omitir módulos cuyo backend no esté disponible (`registry.cpp` L192-L207); no se enumeró una instancia del juego. Las 209 ranuras cuentan solo las 25 tablas públicas actuales; excluyen las 27 ranuras de UiService v1 interno. La matriz cubre todos los IDs y sus fronteras de implementación; no equivale a auditar las 209 ranuras de función ni todo el backend externo.

El registro usa clave `(id, major)`, exige `minor >= minMinor`, rechaza duplicados y valida `ServiceHeader`. Un import requerido ausente impide resolver el mod; uno opcional queda a NULL. ## Flujos profundizados y decisiones de integración

**Actores y stage.** El servicio de stage transforma registros al decodificar la lista; el servicio de actor registra perfiles y solicita instancias al motor. Son caminos complementarios, con distinta temporalidad. El parser llama `stage_apply_actor_edits` antes de crear la instancia y procesa adiciones en sus puntos de carga. `unregister_actor` necesita terminar destrucción antes de retirar el perfil; su fallo no debe ignorarse al gestionar DLL/callbacks. Mantener identidad por ID y comprobar existencia tras transiciones; copiar un `ActorSpawnParams` válido con escala y callbacks correctos. [SDK-001, SDK-021]

**Persistencia.** `set_blob` sólo cambia el almacén en memoria y marca el mod dirty. `save_slot_written` ejecuta primero observadores y después intenta escribir sidecars por mod. La escritura usa `.tmp` y `atomic_replace` por archivo; errores dejan dirty para reintento. Esta secuencia no constituye una transacción atómica entre CARD y todos los sidecars. El mod debe versionar sus propios blobs y validar tamaño/formato al cargar; retirar el bundle no borra datos persistidos. [SDK-020]

**Recursos y presentación.** `ResourceService.load` crea copia del `res/` propio; `OverlayService` cambia el proveedor DVD para lecturas futuras; `TextureService` registra sustituciones del render; `AudioResService` altera catálogos wave/tabla. Esos recursos no tienen idéntico ownership ni momento de aplicación. En hooks o callbacks no retener punteros a buffers ya liberados, cámara de otra escena, texturas por dirección reciclada ni WGPU targets de frame previo. [SDK-002, SDK-003, SDK-009, SDK-018, SDK-019, SDK-022]

**Servicios entre mods.** Preferir imports declarados y `ServiceHeader` para dependencia conocida. Si se usa `HostService.get_service`, observar detach y descartar tabla y punteros del proveedor al retirarse. No basta obtener Http/Net/WebSocket dinámicamente: sus operaciones de apertura comprueban el import declarado. Para callbacks propios conservar rollback explícito de registros parciales; consultar el detalle de loader/errores en [HOOKING_AND_ABI.md](HOOKING_AND_ABI.md). [SDK-REGISTRY, SDK-011, SDK-012, SDK-017, SDK-024]

## Hallazgos que requieren especial cautela

- **ResourceService bool:** las ramas inválidas de `file_exists`/`directory_exists` retornan `MOD_INVALID_ARGUMENT`, cuyo valor es 5. En C++ se convierte a true; la inferencia de conversión es estática y no es un test del juego. No enviar NULL/path no seguro y no tratar esos helpers como validación de argumentos. La investigación no corrige producción. [SDK-019]
- **UI heredada:** disponer de major 1.5 no garantiza todas las operaciones antiguas: `dialog_add_action` retorna `MOD_UNSUPPORTED`. Usar el contrato 2.3 para trabajo nuevo cuando corresponda. [SDK-023]
- **Nulos y punteros de juego:** algunas funciones Actor/GameMode desreferencian entradas sin guarda interna. El contrato no proporciona aislamiento de memoria; validar estado de gameplay y no capturar punteros entre cambios de escena. [SDK-001, SDK-008]
- **DX12:** GfxService entrega interfaz WebGPU/WGPU y no un device D3D12 público del SDK. La adaptación Aurora se observó sólo hasta la frontera de servicio; éxito visual, driver y sincronización del backend siguen NOT_VERIFIED. [SDK-009]
